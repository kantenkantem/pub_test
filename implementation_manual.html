3. 会員側 (一般ユーザー用) 機能実装手順

3.1 宿・プラン検索（Java側での簡単な空室・定員フィルタリング）

初学者がデバッグしやすいよう、複雑なSQL結合を排除し、JPAで取得したListデータをJavaのforループやif文で絞り込む安全で直感的な実装手順です。

  1. パラメータの受け取り: 都道府県ID、キーワード、チェックイン日、チェックアウト日、人数、部屋数を受け取ります。
  2. ベース宿リストの取得: AcmRepository で都道府県とキーワードで絞り込んだ宿の一覧を取得します。
  3. 空室チェック（Java側ループ）: チェックイン日からチェックアウト日の前日まで、各対象日におけるプランの在庫(PlanStock)が必要部屋数以上あるかチェックし、足りない場合はプランを候補から除外します。有効なプランが1つも残らなかった宿も検索結果から除外します。
空室・定員検索コントローラー (AccommodationController.java) 
@GetMapping("/accommodations")
public String searchAccommodations(
        @RequestParam(value = "prefectureId", required = false) Integer prefectureId,
        @RequestParam(value = "keyword", required = false) String keyword,
        @RequestParam(value = "checkInDate", required = false) String checkInDateStr,
        @RequestParam(value = "checkOutDate", required = false) String checkOutDateStr,
        @RequestParam(value = "peopleCount", defaultValue = "1") Integer peopleCount,
        @RequestParam(value = "roomCount", defaultValue = "1") Integer roomCount,
        Model model) {

    // 1. 都道府県とキーワードによる曖昧検索 (JPA標準)
    List rawHotels = acmRepository.findByPrefectureIdAndNameContaining(prefectureId, keyword);
    List resultHotels = new ArrayList<>();

    // 日付指定がある場合の空室判定
    if (checkInDateStr != null && !checkInDateStr.isEmpty() && checkOutDateStr != null && !checkOutDateStr.isEmpty()) {
        LocalDate checkIn = LocalDate.parse(checkInDateStr);
        LocalDate checkOut = LocalDate.parse(checkOutDateStr);
        LocalDate lastNight = checkOut.minusDays(1); // 宿泊日の最終日 (チェックアウト前日)

        for (Accommodation hotel : rawHotels) {
            List rawPlans = planRepository.findByHotelId(hotel.getId());
            List validPlans = new ArrayList<>();

            for (Plan plan : rawPlans) {
                // 定員チェック
                if (plan.getPeopleCount() < peopleCount) {
                    continue; // 定員オーバー
                }

                // 在庫チェック (チェックイン〜チェックアウト前日まで)
                List stocks = planStockRepository.findByPlanIdAndTargetDateBetween(plan.getId(), checkIn, lastNight);
                
                // 滞在期間の日数分、在庫レコードが存在し、すべて必要な部屋数以上残っているか
                long stayDays = java.time.temporal.ChronoUnit.DAYS.between(checkIn, checkOut);
                boolean isAvailable = (stocks.size() == stayDays);
                
                for (PlanStock stock : stocks) {
                    if (stock.getStock() < roomCount) {
                        isAvailable = false;
                        break;
                    }
                }

                if (isAvailable) {
                    validPlans.add(plan);
                }
            }

            if (!validPlans.isEmpty()) {
                // 有効なプランを持つ宿のみを検索結果に登録
                hotel.setPlans(validPlans); // エンティティにプランリストを一時保持 (非永続)
                resultHotels.add(hotel);
            }
        }
    } else {
        resultHotels = rawHotels;
    }

    model.addAttribute("hotels", resultHotels);
    return "accommodation/search";
}

3.2 予約の実行とトランザクション

予約処理は、DBへの書き込みと同時にプラン在庫（PlanStock）の減算を確実に行うため、一連のトランザクションとして扱います。

予約登録ロジック (ReservationService.java) 
@Service
public class ReservationService {

    private final ReservationRepository reservationRepository;
    private final PlanStockRepository planStockRepository;

    public ReservationService(ReservationRepository reservationRepository, PlanStockRepository planStockRepository) {
        this.reservationRepository = reservationRepository;
        this.planStockRepository = planStockRepository;
    }

    @Transactional
    public boolean processReservation(Integer userId, Integer planId, LocalDate checkIn, LocalDate checkOut, Integer peopleCount, Integer roomCount) {
        LocalDate lastNight = checkOut.minusDays(1);
        List stocks = planStockRepository.findByPlanIdAndTargetDateBetween(planId, checkIn, lastNight);

        // 1. 直前の在庫確認
        long stayDays = java.time.temporal.ChronoUnit.DAYS.between(checkIn, checkOut);
        if (stocks.size() != stayDays) return false; // 在庫レコード不足

        for (PlanStock stock : stocks) {
            if (stock.getStock() < roomCount) {
                return false; // 満室
            }
        }

        // 2. 在庫を引く
        for (PlanStock stock : stocks) {
            stock.setStock(stock.getStock() - roomCount);
            planStockRepository.save(stock);
        }

        // 3. 予約レコードの作成
        Reservation reservation = new Reservation();
        reservation.setUserId(userId);
        reservation.setPlanId(planId);
        reservation.setReservedAt(LocalDateTime.now());
        reservation.setCheckInDate(checkIn);
        reservation.setCheckOutDate(checkOut);
        reservation.setPeopleCount(peopleCount);
        reservation.setRoomCount(roomCount);
        reservation.setIsCancelled(false); // 初期値

        reservationRepository.save(reservation);
        return true;
    }
}
予約処理アクションコントローラー (ReservationController.java) 
@PostMapping("/reservations")
public String completeReservation(
        HttpSession session,
        @RequestParam("planId") Integer planId,
        @RequestParam("checkInDate") String checkInDateStr,
        @RequestParam("checkOutDate") String checkOutDateStr,
        @RequestParam("peopleCount") Integer peopleCount,
        @RequestParam("roomCount") Integer roomCount,
        Model model) {

    User loginUser = (User) session.getAttribute("loginUser");
    if (loginUser == null) return "redirect:/login";

    LocalDate checkIn = LocalDate.parse(checkInDateStr);
    LocalDate checkOut = LocalDate.parse(checkOutDateStr);

    // 予約サービスを呼び出し
    boolean success = reservationService.processReservation(
            loginUser.getId(), planId, checkIn, checkOut, peopleCount, roomCount
    );

    if (!success) {
        model.addAttribute("errorMessage", "満室のため予約を確定できませんでした。");
        return "reserve/confirm"; // 確認画面に戻す
    }

    return "redirect:/mypage";
}

4. 管理者側 (従業員用) 機能実装手順

4.1 新規プラン追加時の「180日分の在庫レコード自動生成」

プランを新規登録した際、直後の空室検索にヒットするよう、その日から180日分の PlanStock データを自動で生成します。

プラン登録サービス (PlanService.java) 
@Service
public class PlanService {

    private final PlanRepository planRepository;
    private final PlanStockRepository planStockRepository;

    public PlanService(PlanRepository planRepository, PlanStockRepository planStockRepository) {
        this.planRepository = planRepository;
        this.planStockRepository = planStockRepository;
    }

    @Transactional
    public void createNewPlan(Plan plan, Integer initialStock) {
        // 1. プランの新規登録
        Plan savedPlan = planRepository.save(plan);

        // 2. 本日を起点に180日分の在庫データを作成
        LocalDate today = LocalDate.now();
        for (int i = 0; i < 180; i++) {
            PlanStock stock = new PlanStock();
            stock.setPlanId(savedPlan.getId());
            stock.setTargetDate(today.plusDays(i));
            stock.setStock(initialStock); // 設定した部屋数を初期在庫とする
            planStockRepository.save(stock);
        }
    }
}

4.2 代理キャンセルと「在庫の加算（復元）」

管理者が予約をキャンセル処理した際、履歴は論理削除フラグ（is_cancelled = true）で残し、押さえられていた plan_stocks の在庫数を加算して復元させます。

キャンセル処理サービス (ReservationService.java) 
@Transactional
public void cancelReservationByAdmin(Integer reservationId) {
    Reservation res = reservationRepository.findById(reservationId)
            .orElseThrow(() -> new IllegalArgumentException("予約が見つかりません: " + reservationId));
    
    // すでにキャンセル済みの場合は重複加算を防ぐため即終了
    if (res.getIsCancelled()) return;

    // 1. キャンセルフラグを立てて保存
    res.setIsCancelled(true);
    reservationRepository.save(res);

    // 2. 予約されていた全日程の在庫を、予約されていた部屋数分戻す
    LocalDate lastNight = res.getCheckOutDate().minusDays(1);
    List stocks = planStockRepository.findByPlanIdAndTargetDateBetween(
            res.getPlanId(), res.getCheckInDate(), lastNight
    );

    for (PlanStock stock : stocks) {
        stock.setStock(stock.getStock() + res.getRoomCount());
        planStockRepository.save(stock);
    }
}

5. 初学者がハマりがちなトラブル（Gotchas）対策リスト 共通

実装中に意図しない動作やエラーが出た際は、以下のチェックリストをメンバー全員で確認してください。

⚠️ ハマりがちエラーチェックリスト
  • 1. Thymeleaf での 500 エラー (TemplateInputException)
    原因: HTML内で ${user.name} などと記述しているが、Controller側で model.addAttribute("user", ...) を忘れている。
  • 2. ページアクセス時の NullPointerException
    原因: Repository や Service を使う際、クラス上部で宣言しているがコンストラクタによるDI（依存注入）を行っていない。
  • 3. @Controller と @RestController の選択ミス
    原因: Controllerに @RestController を付けているため、Thymeleaf の画面へ遷移せず、HTML名自体がテキストとして画面に出力されてしまう。
  • 4. HTMLの日付パラメータが LocalDate にマッピングされない
    原因: HTMLの <input type="date"> から Java の LocalDate への自動変換に失敗し、400エラーとなる。対策: 引数で String で受け取ってから LocalDate.parse(dateStr) で変換する。

6. Git コンフリクト回避・解決手順マニュアル 共通

Gitの競合によってコードが先祖返りしたり消失したりするのを防ぐため、以下の手順を守ってプッシュを行ってください。

  1. ブランチの作成: 各自 main ブランチから feature/【機能名】 ブランチを作成して作業します。 
    git checkout -b feature/my-feature
  2. 毎日作業終了前のプッシュ手順: ローカルコミットを実行します。 
    git add .
git commit -m "feat: ○○機能を実装"
  3. mainブランチの変更の取り込み (コンフリクト回避): 自分のブランチに main の最新状態を取り込んでからプルリクエスト（PR）を出します。 
    git checkout main
git pull origin main
git checkout feature/my-feature
git merge main
⚠️ コンフリクトが発生したら

もしマージの際にコンフリクト（衝突）が発生した場合は、Eclipseやエディタ上で衝突箇所（<<<<<<< や =======）を確認し、手動でコードをマージしてから再度コミット・プッシュを行ってください。

Section 6 の確認項目
  • 毎日、実装ブランチをプッシュする前に main から最新コードをマージする習慣を身につけた
