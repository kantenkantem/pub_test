1. 3日間の開発ロードマップ

限られた時間内で動作可能なシステム（一次開発スコープ）を確実に作り上げるため、以下の順序でタスクをこなしてください。ブラウザ上で進捗をチェックできます。

  • 【Day 1 (6/10)】環境構築・共通基盤作成・画面モックの表示
  • データベース（DB）の作成: 最新のテーブル定義に従い、テーブルを構築（マスタデータとして prefectures を先行インサート）。
  • Entity・Repository の共通作成: 代表者が entity（手動Getter/Setter）と repository の枠組みを一括作成し、GitにPush。他メンバーはこれをプルして開発開始。
  • 画面モックの表示: コントローラーからThymeleafを表示し、リンク遷移図通りにモック画面が切り替わる状態を初日中に完成させる。
  • Gitブランチ運用の開始: 各自 feature/【担当機能】 ブランチを作成して作業。
  • 【Day 2 (6/11)】コアロジック（空室検索・プラン在庫連動・予約）の実装
  • 空室検索ロジックの実装: 指定した日付範囲で plan_stocks の在庫が足りているプランのみを検索・表示する処理を開発。
  • 予約時の在庫減算処理: 予約確定時にトランザクションを張り、滞在日数分の plan_stocks の stock を減算するサービスロジックを実装。
  • 一般会員機能の統合: 新規登録 → ログイン → 検索 → 予約 → 履歴確認の結合テスト。
  • 【Day 3 (6/12)】管理者機能の完成・代理キャンセル・結合テスト
  • 管理者機能（宿・プランのCRUD）の実装: 宿やプランの追加・編集・アーカイブ処理を完了。
  • 代理キャンセルと在庫復元: キャンセル時に予約分の plan_stocks を加算（復元）する処理を実装。
  • 結合テストの実行: ドキュメント相互のクロスチェックリストを元に全員でテスト。

① Entity (PlanStock.java)

src/main/java/com/example/teamdev/entity/PlanStock.java 
package com.example.teamdev.entity;

import jakarta.persistence.*;
import java.time.LocalDate;

@Entity
@Table(name = "plan_stocks")
public class PlanStock {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;

    @Column(name = "plan_id", nullable = false)
    private Integer planId;

    @Column(name = "target_date", nullable = false)
    private LocalDate targetDate;

    @Column(name = "stock", nullable = false)
    private Integer stock;

    // デフォルトコンストラクタ（JPA用）
    public PlanStock() {}

    // ゲッターとセッターを手動作成
    public Integer getId() { return id; }
    public void setId(Integer id) { this.id = id; }

    public Integer getPlanId() { return planId; }
    public void setPlanId(Integer planId) { this.planId = planId; }

    public LocalDate getTargetDate() { return targetDate; }
    public void setTargetDate(LocalDate targetDate) { this.targetDate = targetDate; }

    public Integer getStock() { return stock; }
    public void setStock(Integer stock) { this.stock = stock; }
}

③ Service (ReservationService.java)

src/main/java/com/example/teamdev/service/ReservationService.java 
package com.example.teamdev.service;

import com.example.teamdev.entity.PlanStock;
import com.example.teamdev.repository.PlanStockRepository;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import java.time.LocalDate;
import java.util.List;

@Service
public class ReservationService {

    private final PlanStockRepository planStockRepository;

    public ReservationService(PlanStockRepository planStockRepository) {
        this.planStockRepository = planStockRepository;
    }

    // 予約実行時に在庫を減らすトランザクション
    @Transactional
    public boolean reserveRoom(Integer planId, LocalDate checkin, LocalDate checkout, Integer roomCount) {
        LocalDate lastNight = checkout.minusDays(1);
        List stocks = planStockRepository.findByPlanIdAndTargetDateBetween(planId, checkin, lastNight);

        // 1. 在庫の有無を確認
        for (PlanStock stock : stocks) {
            if (stock.getStock() < roomCount) {
                return false; // 在庫不足
            }
        }

        // 2. 在庫の減算を実行
        for (PlanStock stock : stocks) {
            stock.setStock(stock.getStock() - roomCount);
            planStockRepository.save(stock);
        }

        return true;
    }
}

④ Controller (ReservationController.java)

src/main/java/com/example/teamdev/controller/ReservationController.java 
package com.example.teamdev.controller;

import com.example.teamdev.service.ReservationService;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;
import java.time.LocalDate;

@Controller
public class ReservationController {

    private final ReservationService reservationService;

    public ReservationController(ReservationService reservationService) {
        this.reservationService = reservationService;
    }

    // フォームクラスを使わず直接 @RequestParam で受け取り、バリデーションを行う
    @PostMapping("/reservations")
    public String completeReservation(
            @RequestParam("plan_id") Integer planId,
            @RequestParam("checkin_date") String checkinDateStr,
            @RequestParam("checkout_date") String checkoutDateStr,
            @RequestParam("room_count") Integer roomCount,
            Model model) {

        // 簡易バリデーション
        if (planId == null || checkinDateStr.isEmpty() || checkoutDateStr.isEmpty() || roomCount == null) {
            model.addAttribute("errorMessage", "必須項目が入力されていません。");
            return "reserve/new";
        }

        LocalDate checkin = LocalDate.parse(checkinDateStr);
        LocalDate checkout = LocalDate.parse(checkoutDateStr);

        boolean success = reservationService.reserveRoom(planId, checkin, checkout, roomCount);

        if (!success) {
            model.addAttribute("errorMessage", "指定された期間は満室となっております。");
            return "reserve/new";
        }

        return "redirect:/mypage";
    }
}

PlanService 内での登録・在庫自動生成ロジック 
@Transactional
public void addPlanAndGenerateStocks(Plan plan, int roomCount) {
    // 1. プランを保存
    Plan savedPlan = planRepository.save(plan);

    // 2. 本日から180日後までの在庫レコードを自動生成
    LocalDate today = LocalDate.now();
    for (int i = 0; i < 180; i++) {
        PlanStock stock = new PlanStock();
        stock.setPlanId(savedPlan.getId());
        stock.setTargetDate(today.plusDays(i));
        stock.setStock(roomCount); // 設定された初期部屋数を在庫とする
        planStockRepository.save(stock);
    }
}

3. 初学者が陥りがちな「5大エラー（Gotchas）」と対策

警告: 実装中、エラーで手が止まったらまずここを確認してください！
  • 1. @Controller と @RestController の取り違え
    現象: 画面が表示されず、HTML名（文字列）がそのまま画面に表示される。
    対策: Thymeleafを使って画面遷移を行うコントローラーは、必ず @Controller アノテーションを使用します。@RestController はAPI制作用なので使用しないでください。
  • 2. アノテーション忘れ（Bean登録・JPA）
    現象: 起動時に BeanCreationException が起きる、または NullPointerException が発生する。
    対策: Serviceクラスには @Service、Repositoryには @Repository、トランザクション処理を行う箇所には @Transactional が付いているか必ず確認してください。
  • 3. HTMLの date 入力と LocalDate の変換エラー
    現象: 日付を送信すると MethodArgumentTypeMismatchException (400 Bad Request) が発生する。
    対策: HTMLの <input type="date"> は yyyy-MM-dd 形式の文字列で送信されます。Controller側では String で受け取り LocalDate.parse() を呼ぶか、引数に @DateTimeFormat(pattern = "yyyy-MM-dd") LocalDate checkinDate のようにフォーマット指定を明示してください。
  • 4. DBカラム名と Entity プロパティ名の不一致
    現象: DBアクセス時に SQLGrammarException (カラムが見つかりません) が発生する。
    対策: DBカラムが prefecture_id (スネークケース) の場合、Entityの変数名を prefectureId (キャメルケース) とした上で、@Column(name = "prefecture_id") アノテーションを明示してください。
  • 5. Git のコンフリクト多発
    現象: プル・プッシュ時に競合が発生してコードが失われる。
    対策: 各メンバーの担当Controller・HTMLを完全に分担（下記4章参照）し、共通ファイル（application.properties や CSS）を触る際は必ず声をかけて、編集後即時プッシュ・マージ・共有を徹底します。

    - GET /admin/reservations keyword, date AdminResController listReservations 全予約一覧・検索画面の表示
    - GET /admin/reservations/{id} id AdminResController showResDetail 特定の予約詳細画面の表示
    - POST /admin/reservations/{id}/cancel id AdminResController cancelReservation 予約キャンセル処理（代理キャンセル ＋ 在庫復元）

    6. ドキュメント相互のクロスチェックリスト

    • 画面遷移図と画面レイアウトの整合性: 遷移図にある画面が、画面レイアウトにすべて漏れなく記述され、遷移先と一致しているか。
    • 画面レイアウトとURLマッピングの整合性: 画面レイアウトのボタン・リンク要素が、マッピング表のパス・メソッドと一致しているか。
    • 画面レイアウトとテーブル定義の整合性: 画面レイアウトの入力桁数・選択肢が、テーブル定義のカラム型・サイズと一致しているか。
    • ユースケース記述とプログラム構造の整合性: ユースケース記述の「基本系列」の手順が、コントローラー・メソッドの処理内容と一致しているか。
